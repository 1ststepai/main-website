Base: e1c7c7696b08d9a47959d7f1be8be2c882b5cf39. Rollback: retain commercial candidate.

3. Build Machine: visitor advances an explicitly illustrative request through context, architecture, workstreams, verification, launch, and handoff. Pieces converge visually; completion is labeled as an example, never real execution or proof of verification.
4. Process: four compact numbered rows along one continuous line. No card grid.
5. Proof: two approved source-linked reviews, concise OS concept link, service links, and native disclosure FAQ with unchanged schema answers.
6. Close: clear three-path intake links.

Compress the problem section, service grid, founder narrative, OS diagram and FAQ into proof/disclosure. Preserve deep-route access and social metadata. No new dependency or backend/analytics/intake change.

Assets: existing canonical logo; new direct browser capture of https://www.daysetgo.ai/plan?mode=demo on 2026-09-22. Planner is a demo sandbox with fictionalized/unverified itinerary content, labeled accordingly. No authenticated/customer data captured. No new Job Agent/Nova mock interface.

Risks: large screenshot bytes (optimize to WebP); scroll transforms (one rAF read/write batch, offscreen skip); mobile overflow (bounded scene, no hover dependency); reduced motion (static transforms and all content retained). No WebGL, autoplay video, scroll interception, or infinite animation. Keyboard and pause controls remain available.
