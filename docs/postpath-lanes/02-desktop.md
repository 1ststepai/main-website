# Lane 2 — PostPath Mac / Windows developer preview

Owner: desktop lane (`packages/postpath-desktop`, `packages/social-mcp/scripts`, `public/downloads/postpath`).

This package is a **developer preview**. It requires **Node.js 20+** and a local app payload. It is **not** a one-click installer. `manifest.json` records `signed: false` and `kind: developer-preview`.

Signing and notarization are **blocked**. This environment has no Apple Developer ID and no Windows Authenticode certificate. Nothing here disables Gatekeeper or SmartScreen, and no certificate was purchased or invented.

## What shipped

`packages/social-mcp/scripts/build-downloads.sh` keeps main's Node.js 20+ launcher checks (version parse, dialog, first-run errors, Windows pause-on-failure). It does **not** replace those with the shorter PR 38 launchers, and it does **not** reuse PR 38's unversioned zip blobs. The script rebuilds the archives.

Version comes from `packages/social-mcp/package.json` (`0.1.0`) and is embedded in the zip filenames and in the manifest.

| File | Role |
| --- | --- |
| `PostPath-<version>-macOS-developer-preview.zip` | macOS folder: launcher, README, `postpath-app.tgz` |
| `PostPath-<version>-Windows-developer-preview.zip` | Windows folder: `.bat`, `.ps1`, README, `postpath-app.tgz` |
| `SHA256SUMS.txt` | `sha256sum -c` compatible checksums of those zips |
| `manifest.json` | `version`, `gitSha`, `nodeRequirement`, `signed: false`, `kind: developer-preview`, plus per-zip sha256 |

`gitSha` is the commit the script read at pack time (`git rev-parse HEAD`), not a promise that the archive commit hash equals that value. The loose `postpath-app.tgz` is not published; `.gitignore` ignores `public/downloads/postpath/postpath-app.tgz` if a build leaves one behind.

Checkout launchers under `packages/social-mcp/scripts/Open-PostPath.*` stay the in-repo entry points (run the working tree). The copies inside the zip unpack into `~/.postpath/app` and are generated by the build script.

Rebuild from the repo root:

```bash
bash packages/social-mcp/scripts/build-downloads.sh
```

## Fresh install (zip layout)

1. Install Node.js 20 or newer from `https://nodejs.org`.
2. Unzip the platform archive somewhere you can write.
3. macOS: double-click `Open PostPath.command`. If Gatekeeper reports an unidentified developer, right-click that file and choose Open. Do not turn Gatekeeper off.
4. Windows: double-click `Open-PostPath.bat`. SmartScreen may warn because the preview is unsigned. Do not turn SmartScreen off.
5. The first launch creates `~/.postpath/app` (`%USERPROFILE%\.postpath\app` on Windows), unpacks `postpath-app.tgz`, and runs `npm install --omit=dev` once.
6. In the desk, save OAuth credentials, register `http://127.0.0.1:47831/oauth/callback`, connect accounts, then Enable in Cursor.

`POSTPATH_NO_OPEN=1` starts the desk without asking the OS to open a browser. The default launch still opens the desk.

## Relaunch

Quit the desk (Ctrl+C in the launcher window). Run the same launcher again. When `~/.postpath/app/bin/social-mcp.js` is already there, the launcher prints `Relaunch: using existing app at ...` and does not unpack or reinstall.

## Upgrade

1. Quit PostPath.
2. Delete only the app directory: `~/.postpath/app` (Windows: `%USERPROFILE%\.postpath\app`).
3. Unzip the newer developer-preview zip and run its launcher.
4. Do not delete `~/.social-mcp`. The new process keeps the existing vault.

## Credentials

The vault lives in **`~/.social-mcp`** (override with `SOCIAL_MCP_HOME`). Tokens and `oauth.env` are created there by the desk, not inside the zip and not inside `~/.postpath/app`.

Uninstall and upgrade do **not** delete the vault.

## Uninstall

1. Quit PostPath.
2. Delete the unzipped preview folder.
3. Delete `~/.postpath` (the unpacked app and its `node_modules`).
4. Leave `~/.social-mcp` in place unless you separately intend to erase saved connections.

## Electron shell

`packages/postpath-desktop` is a thin window around the same desk. It does not fork desk business logic.

- `contextIsolation`, `sandbox`, and `webSecurity` are on. `nodeIntegration` is off.
- `will-navigate`, `will-redirect`, and `setWindowOpenHandler` share one rule: only the desk origin stays in the window; other `http:` / `https:` URLs are sent to `shell.openExternal`; other schemes are dropped. Extra Electron windows are denied.
- Desk stdout/stderr lines containing `token`, `secret`, `password`, `authorization`, `api_key`, or `oauth` are redacted before they are written.

From a checkout:

```bash
cd packages/social-mcp && npm install
cd ../postpath-desktop && npm install && npm start
```

`npm test` in `packages/postpath-desktop` does not launch Electron.

Executed on this Linux host (Node v22.23.4). macOS GUI, Gatekeeper, and double-click of `Open PostPath.command` were **NOT TESTED**. Windows, SmartScreen, `Open-PostPath.bat`, and `Open-PostPath.ps1` were **NOT TESTED**. Signing is blocked: no Apple Developer ID and no Windows certificate in this environment.

### Linux zip path (ran)

Unpacked `PostPath-0.1.0-macOS-developer-preview.zip` into a temporary directory and ran `Open PostPath.command` with `HOME` set to that temporary directory and `POSTPATH_NO_OPEN=1`. That exercises the bash launcher on Linux. It is not a macOS test.

- Fresh install printed `First run: unpacking PostPath developer preview 0.1.0 and installing dependencies...`, ran `npm install --omit=dev`, then served `http://127.0.0.1:47830/` (HTTP 200, title `PostPath by 1stStep.ai`).
- App files landed in `$HOME/.postpath/app` (`bin/social-mcp.js` present).
- The vault was created at `$HOME/.social-mcp` (`master.key` and `media/`). The real login home was not used.
- Stopped the process. Port 47830 closed.
- Relaunch printed `Relaunch: using existing app at .../.postpath/app` and served HTTP 200 again without a second install.
- Uninstall removed the unzipped folder and `$HOME/.postpath`. `$HOME/.social-mcp/master.key` was still there afterward.
- Launcher logs did not contain token, secret, password, authorization, api_key, or oauth lines.

### Electron on Linux (ran, narrow)

`npm install` inside `packages/postpath-desktop` downloaded Electron 37.10.3 only (binary about 192 MB; no extra browser or certificate tooling). `xvfb-run -a ./node_modules/.bin/electron .` with a temporary `HOME` started the shell, spawned `node .../social-mcp.js app --no-open`, and the desk returned HTTP 200. Stdout used the `[postpath-desk]` prefix and did not contain credential assignments. Chromium logged a GPU-process init error and missing system D-Bus; the window process stayed up anyway. No clicks, OAuth, or external-link navigation were performed. macOS and Windows Electron GUIs were **NOT TESTED**.

The temporary homes, including the generated vaults, were deleted after the checks.
