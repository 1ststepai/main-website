# G1.5 zero-cost rule inventory — candidates, not Audit results

**2026-09-13 · ADR-OS-003.** This extends the [six-system inventory](OS_G1_5_FIRST_PARTY_ECOSYSTEM_AUDIT.md) and [methodology review](OS_FREE_AUDIT_FIRST_PARTY_METHOD_REVIEW.md). It is a design classification of checks exposed by read-only first-party inspection, **not** six finalized baselines, approved `PatternDefinition` entries, production detectors, verified security findings or a working free report. Source evidence is local Git/config/source/document inspection and bounded public HTTP observations; source-to-production commit identity, private provider data and owner consent remain unverified where noted. The separate OS Audit validator failed five upstream-lock checks during G1.5; its lock file was later updated, and `python tools/validate_foundation.py` now passes on recheck. The review/ratification provenance of that update was not verified; no engine or customer run exists.

**Feasibility:** DETERMINISTIC NOW means a reproducible read/check or existing local validator can supply a fact today, not that a free engine already ships it. DETERMINISTIC WITH TOOLING requires an allowlisted parser/probe plus independent fixtures. USER INPUT REQUIRED needs a verified owner/provider answer or consent; a user assertion is labeled as such. PAID INTELLIGENCE means nuanced human/model reasoning belongs after separate activation, not mandatory metered inference in the free result. NOT WORTH AUTOMATING means no defensible broad rule. “Free” below means **no metered AI/API charge**; retrieval, CPU and storage still cost resources. Severity is **conditional rule logic**, never an actual severity assigned to one of these systems.

## Rule-engine contract to resolve before implementation

An approved rule needs stable ID/version, scope and applicability, deterministic detector, bounded input selection, required evidence source/plane/freshness and search coverage, severity and confidence logic, explanation, remediation class, verification method, privacy classification, reviewer, provenance and retirement/version policy. A reviewed `PatternDefinition` is **not executable** solely because its prose is approved. The current draft `PatternDefinition` schema has no detector/evidence/severity fields; reconcile it with the separate Audit control registry instead of creating a second authority or auto-transforming customer data into cross-project patterns. AI can help internal reviewers propose candidates once, but production free runs evaluate only reviewed deterministic rules and never require that inference.

The free dependency graph must cover **baseline → Genome → checks → findings/strengths/unknowns → priorities → OS/agent recommendation → report** without invoking a metered provider on success, failure, retry, cache miss or fallback. An identical *permissioned* baseline can reuse safe results only with scope, content/dirty manifest (not just commit), engine/control/pattern versions, environment evidence freshness and tenant authorization in the cache contract; never share raw private evidence across tenants. Rate/size/time/concurrency/retention limits, infrastructure-cost telemetry, zero external metered usage telemetry and a negative dependency/call-boundary test are needed before `FREE-AUDIT-ZERO-METERED-COST` can PASS. Today the gate is **NOT_EVALUATED** and production remains closed.
